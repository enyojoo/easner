## Screen harnesses

`/dev/screens/<posts|authors|my-profile|media|categories|settings>` mounts the real page component inside the real `AdminShell`, with an in-memory seeded query cache and a stand-in auth context (`?role=writer|editor|owner`, `?empty=1`). Reading works; saving is not wired and shows its error toast. Enabled only with `NODE_ENV=development` and `ADMIN_DEV_HARNESS=1`; the dev layout answers 404 otherwise and the page imports the harness behind a build-time `NODE_ENV` check. Existing: `/dev/editor` (editor with every panel tab), `/dev/analytics`, `/dev/overview`, `/dev/redirects`.

## Analytics: what is left

- **On the site now.** Not built. The adapter (`lib/analytics/posthog.ts`) only runs the nightly day queries from a server job; nothing reads PostHog live. It needs a server route (like `/api/analytics/status`, bearer token checked against `admin_members`) that runs one HogQL query, `select count(distinct distinct_id) from events where event = '$pageview' and timestamp > now() - interval 5 minute`, cached for 30 seconds, and a client hook polling it. No SQL, but it needs the real PostHog key to verify.
- **Funnel.** Needs the steps the card draws as events: visit (`$pageview`), product page view, `cta_clicked` with `destination_type` in the sign-up set, and the sign-up completion event. The nightly job would write one row per day and step into a new rollup, `site_funnel_daily(date date, step text, visitors integer, primary key (date, step))` (migration prefixed 20261121, members read, service role writes), from a HogQL funnel or three `count(distinct distinct_id)` queries per day. Visitors per step cannot be added across days without double counting, so the card's funnel is per day summed, as the other visitor numbers are.
- **Location map.** Country and city rows already exist (`site_breakdown_daily`, dimensions country and city). What is missing is geography: country centroids for a country map (a static table in the client, no SQL) or city latitude and longitude for the city map the card draws. PostHog gives `$geoip_latitude` and `$geoip_longitude`; the job would store a rounded pair per city in `site_city_geo(city text primary key, country text, lat numeric, lon numeric)`. The BarList of countries and cities stands in for it.
- **Redirect hits.** `hits in 30 days` would need the website to count redirects (middleware event to PostHog, `redirect_hit` with `from`), then a `redirect_hits_daily(date, from_slug, hits)` rollup.

## Needs you for Writers

Overview shows Needs you to Editors and Owners only (reviews waiting, second approvals, posts going live in 48 hours). Writers see their own posts sent back for changes under a "Needs you" tab on the Posts list (shown only while something waits) and in the amber count on the Posts nav item. Editors and Owners get the same tab for posts in review.

## The Card padding bug and how it is held

`Card` pads only top and bottom; text placed straight inside touches the edges. Audit of every `<Card` in `admin/`: only the Overview pipeline tiles and the new Overview blocks had it (the earlier "two dozen" were `padding="none"` cards that hold tables or an `EmptyState`, which pad themselves). Rule now: use `CardHeader` and `CardContent`, or `CardBody` (24 px sides), or `padding="none"` with your own padding. `lib/card-padding.test.ts` reads the source and fails a `<Card>` whose first child is a bare element without a `px-` class.

## Clipping

The "clipped" look was the missing card padding plus the cards' own tight layout; the shell itself does not clip. The sidebar is fixed, the header is outside the scroll area, and only `main` scrolls, so nothing hides under the header.
